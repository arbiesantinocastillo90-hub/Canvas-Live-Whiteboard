# Roadmap and milestone acceptance

Status reviewed **October 20, 2026**. This roadmap retains milestone numbers 0–8 from the [original specification](../PROJECT_SPEC.md). It describes supported behavior and the work needed for acceptance; the [timeline](TIMELINE.md) records actual development dates.

Canvas Live is a local-first, single-user whiteboard with an optional MCP companion. Its renderer is original SVG code. Excalidraw was an initial candidate; adoption is deferred and does not block the implemented editor. A future engine change would require a new runtime and license review.

“Implemented” means the supported scope has code and recorded checks. It does not mean every proposed feature exists, an external AI account has passed acceptance, or another physical computer has been tested.

## Current verification baseline

The October 20 [refinement report](BUGS_REFINEMENTS_VERIFICATION.md) records **1,205 application tests**, **71 MCP tests**, **22 isolated browser scenarios**, and native suites of **67 new** and **55 existing checks**, together with passing type, lint, formatting, build and license checks. It covers individual record recovery, lightweight Home browsing, Trash/transfers, independent explicit grants and the interactive AI mini. These are dated results for the checked build, rather than a permanent statement about every checkout.

The earlier October 18 [rich-canvas report](RICH_CANVAS_VERIFICATION.md) separately records native media and portable-launcher checks. These suites overlap with later runs; their counts should not be added into a total or treated as proof of an external AI connection.

## Next work, in priority order

1. **Close external AI acceptance (milestone 6).** Configure the owner's supported client and tunnel locally, complete the documented read/edit/Undo/revocation flow on a disposable canvas, and record observed results without publishing credentials. Preserve a useful offline editor if the external service is unavailable.
2. **Test another Windows computer (milestone 7).** Run the complete USB package under a normal user account without globally installed Node. Verify startup, saved library/media, changed drive letters, shutdown and relaunch. For school computers, record whether local policy permits the executables and required network connection; administrator access is not an acceptance assumption.
3. **Prepare a reproducible public release (milestone 7).** Rebuild from a clean checkout, rerun relevant checks, document the exact tested commit and package contents, and publish checksums and setup/recovery steps. Keep source publication, a tagged release and an installed private package distinct.
4. **Measure practical limits.** Add repeatable large-board and media-use measurements on the target hardware, review keyboard/accessibility flows and prioritize defects found by real use. Existing bounds and automated test counts are not performance measurements.
5. **Evaluate editor extensions from user needs.** Freehand drawing and further layout tools are candidates. New functionality should reuse validated operations and retain file compatibility. Revisit a third-party renderer only if a concrete requirement justifies migration.
6. **Explore multiplayer after MVP acceptance (milestone 8).** Begin with a documented conflict and authorization model before committing to transport or hosting.

No future completion dates are assigned. Each item closes when its acceptance evidence exists.
