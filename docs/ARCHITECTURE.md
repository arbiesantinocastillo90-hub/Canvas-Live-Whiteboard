# Architecture

## Implemented foundation

`src/main.tsx` mounts a React app under StrictMode. `src/app/App.tsx` controls Options, Projects and Work. `AppearanceOptions.tsx` controls the theme preferences, `ProjectDialog.tsx` handles project names, and `workspace.ts` validates and persists bounded project metadata/preferences in browser localStorage. CSS uses shared light/dark tokens, system fonts and original inline SVG controls. The owner-provided logo is a local unchanged PNG.

Vite serves the app on loopback. Vitest uses the same React plugin with a jsdom test environment. TypeScript checks application and configuration code; Oxlint and Prettier provide code/format checks. `scripts/check-licenses.mjs` generates an inventory from the resolved dependency lockfile and flags unknown/unaccepted license metadata.

`FileWorkspace.tsx` organizes project-scoped files, open tabs, name dialogs, import/export, explicit document saving and panel context. `lcanvas.ts` validates LCANVAS v2 and migrates valid v1 files in memory. `canvasFiles.ts` stores each record in IndexedDB with a project index and checks ownership on every read/write. Opening a v1 record updates its recency without rewriting its payload; Save writes v2. Failed storage retains a session overlay and reports the limitation. Existing localStorage v1 project/theme metadata is unchanged. Files have no arbitrary count cap; documents are bounded to 10 MiB, 5,000 elements and 100 layers. There is no cross-tab conflict resolution yet.

`CanvasEditor.tsx` renders original SVG geometry and literal text with pointer and keyboard editing. `CanvasInspector.tsx` applies properties and manages layers. Both use the pure validated `canvasOperations.ts` functions for stable-ID creation, updates, movement, resizing, deletion, containment and connections. Geometry and ordering helpers also serve the retained read-only viewer. `editorHistory.ts` combines content and viewport transactions with at most 100 retained snapshots and a 32 MiB history estimate; large documents retain fewer steps. The operations and history are independent of any MCP transport.

Closing tabs never deletes files. Content and view changes stay in memory until Save; export includes the current state. `canvasDrafts.ts` retains unsaved drafts through section/project navigation and protects page unload while the app remains open. Reopening a file starts new undo history. `useCanvasFocus.ts` hides surrounding layout, requests native fullscreen when available, fits the canvas and restores layout on exit; embedded browsers retain an app focus fallback. See [LCANVAS.md](LCANVAS.md) and [EDITOR.md](EDITOR.md).

No third-party drawing engine has been adopted. Excalidraw licensing/runtime evaluation remains separate from the implemented editor. The MCP companion uses the official TypeScript SDK v2; its bridge and shared operations are described below.

## Adaptable workspace

`layout.ts` validates and persists bounded panel preferences under its own localStorage key. `PanelResizeHandle.tsx` provides pointer capture and accessible keyboard adjustment. App/FileWorkspace/CanvasEditor use the same layout model; Workspace AI's painted width is measured for insertion and view fitting. Full screen temporarily hides panels and restores the ordinary layout on exit. These preferences never enter the LCANVAS model or MCP content stamp.

`WorkspaceCommands.tsx` owns the palette, current-project quick switcher and shortcut recorder. `workspaceCommandsContext.ts` registers current handlers without capturing stale document state; `shortcuts.ts` validates bindings and restores safe defaults from invalid storage. Keyboard routing protects input, composition, dialogs and resize controls. Provider-managed shortcuts replace legacy local defaults, so clearing or remapping an action is effective. Overlays render inside the native fullscreen element when required. Commands invoke existing UI operations rather than defining a second mutation path.

`appearance.ts` resolves shared palette and motion tokens from existing preferences. Optional colors, contrast and motion settings have backwards-compatible defaults. `workspace-adaptable.css` applies the final panel and compact-workspace rules. App and operating-system reduced-motion settings take precedence. See [Adaptable workspace](ADAPTABLE_WORKSPACE.md).

## Implemented Windows launcher

`launcher/CanvasLiveLauncher.cs` is a small Windows GUI executable built with the laptop's .NET Framework compiler. `scripts/package-windows.ps1` places it beside the production website under `release/Canvas Live/app`. It uses its own executable location, so the complete folder can be moved and launched from another working directory. The runtime is supplied by Windows; no Node.js process or new third-party runtime is packaged.

The launcher hosts an exact whitelist of packaged static files through a loopback-only TCP listener, then asks Windows to open the local URL in the default browser. It supports GET/HEAD, validates Host and paths, bounds headers and simultaneous connections, and provides a read-only instance health endpoint. A per-user, per-folder mutex and health check make repeated launches reopen the existing instance. A Windows tray menu provides Open and Close actions. Its endpoint/error files live under `%LOCALAPPDATA%/Canvas Live/launchers/<package-key>`.

The preferred port is 4173; an occupied port selects an available loopback port. Browser metadata and IndexedDB files are scoped to that origin, including the port; a fallback port opens a separate file library. LCANVAS exports are portable backups. The native launcher hosts static files. The package includes a separately started optional MCP companion bundle and ChatGPT setup helper; Node.js 24 is required for that companion and is not redistributed. See [WINDOWS_LAUNCHER.md](WINDOWS_LAUNCHER.md).

## Implemented MCP companion and browser bridge

`server/main.ts` starts a loopback HTTP companion at port 8787. `server/http.ts` authenticates `/mcp` and browser bridge requests with distinct random 256-bit credentials, validates exact Host/origin/methods, bounds message sizes and applies rate limits. `server/tools.ts` registers 15 strict SDK tools and structured results. `src/mcp/canvasCommands.ts` validates commands, uses the existing pure operations and bounds reads to 100 objects, transactions to 25 operations and cumulative deletion to 10 objects. There are no filesystem, shell, save/export, reset-all or unrelated-document tools.

`launcherOrigin.ts` handles the native website launcher's ephemeral fallback port. At startup, a companion inside the packaged folder reads only that folder's hashed launcher registration and adds its exact origin after a bounded, no-redirect health check matches the package identity. Missing, malformed, stopped or foreign registrations add no origin. Open the native website before its companion; restart the companion if the website's port changes. Other loopback ports are not broadly authorized.

`useMcpBridge.ts` pairs only after an explicit Share this canvas action; the browser token remains in memory. One tab can own the connection. Sequential 500 ms polling publishes committed state and carries operations/acknowledgments. The editor rejects operations during pointer gestures and routes successful AI transactions through its existing history. A write is successful only after browser acknowledgment. Session IDs, revisions and expiring commands reject switched files, stale/manual edits and late execution. Operation IDs cache identical retries without duplicate mutation, including late acknowledgment after a timeout. Manual edits between execution and acknowledgment preserve the latest state. The server permits 128 logical operations per sharing session; share again to renew it.

Leaving Work, switching files, Stop sharing, or five seconds without a browser heartbeat ends authority. Closing the AI panel keeps sharing active. Reads use the latest acknowledged/published browser snapshot, which can lag a manual edit by a polling interval; revision checks at browser execution protect writes. Sharing includes unsaved content and hidden objects in that one document. AI changes remain unsaved until Save. Browser history is session state and resets when reopening a file.

Full document revisions include saved viewport changes. `canvasRevision.ts` serializes document content excluding only the viewport, and the browser publishes the last full revision at which that content changed alongside its snapshot. The companion advertises support at connection, then validates and tracks this stamp, including content changes followed by navigation before publication. Ordinary requests accept a read from that content revision through the current full revision and include a matching content stamp for browser validation. This permits completed pan/zoom without replacing the current view. Content mutations invalidate older or queued writes. Undo/Redo require exact full revisions because navigation is part of history. The browser omits the new poll field for older companions and retains exact revision checks for their requests without a content stamp.

The MCP endpoint uses SDK Streamable HTTP with compatibility for supported older clients. ChatGPT web can use OpenAI Secure MCP Tunnel with a locally injected bearer credential; the development website and browser bridge remain private. The helper never starts a tunnel automatically. A desktop plugin package declares local Streamable HTTP and prompts for a separate MCP credential. Local protocol and actual browser tests establish the integration. The owner's plugin is installed and has read the shared canvas; live editing after the revision fix remains to be confirmed. No model inference API is used. See [CHATGPT_MCP.md](CHATGPT_MCP.md) and [MCP_VERIFICATION.md](MCP_VERIFICATION.md).
